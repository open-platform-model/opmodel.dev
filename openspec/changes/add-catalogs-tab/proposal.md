## Why

The catalog members are the reference a module author reads most, and they change per catalog minor: a field added in opm 4.5 is not in 4.4. Today they are one copy in Reference, generated by catalog_opm's `tools/refgen`, committed to git and read at whatever tree the `v1.0` line resolves to. A reader on 4.4 cannot see 4.4's members once 4.5 ships, and a doc-comment fix needs a catalog release.

docs-kit (owner decisions of 2026-10-02, `docs-kit DESIGN decision 2`, `5`, `8`, `9`) moves the catalog reference into signed OCI docs bundles that catalog_opm's CI publishes per release and per push to `main` (`edge`), and later per docs revision (docs-kit `add-docs-revisions`; the site needs no change for it). This change is the site's half of docs-kit's phase 1: pull those bundles and show them as a **Catalogs** tab, one entry per opm minor from 4.4 on, switchable on its own, outside the site versions. Its sibling changes are docs-kit `build-opm-docs-phase-1` (the tool and the contracts it fixes, cited here as `docs-kit C1` to `C12`) and catalog_opm `publish-docs-bundle`.

## What Changes

- A new **Catalogs** tab in the navbar between Reference and Enhancements, shown only when the build has catalog bundles.
- An unversioned section built in the same Hugo run, outside `/<version>/`, mounted into the default version only (the Enhancements pattern):
  - `/catalogs/`: a section page listing the catalogs (today one, opm);
  - `/catalogs/opm/<MAJOR.MINOR>/...` for every opm minor from 4.5 on (amended 2026-10-03; was 4.4), and `/catalogs/opm/edge/...` ("main (unreleased)"), each from its own pulled bundle, with its own sidebar;
  - the landing of each minor is the authored catalog contract page that catalog_opm ships in the bundle.
- A version switcher on every catalog page: newest minor first, `edge` last; it keeps the reader on the same page when the chosen minor has it, else the nearest parent, else that minor's landing.
- Aliases: `/catalogs/opm/` to the newest minor, `/catalogs/opm/<MAJOR>/` to the newest minor of that major, `/catalogs/opm/<MAJOR>/<path>/` to the same path there; as `_redirects` lines and as meta-refresh stubs for hosts that ignore them (GitHub Pages today). `edge` gets no alias.
- Indexing: only the newest minor of each major is indexed, listed in `llms.txt` and in the sitemap; older minors and `edge` are `noindex`. Every minor and `edge` has its own Pagefind index, and search from a catalog page stays in that minor.
- A new build input, pulled by a new network step, `task bundles:pull`: `opm-docs pull` (pinned by version and SHA-256 in the build image) resolves the tab's tags in GHCR, verifies each bundle's Sigstore signature, unpacks it to `site/.bundles/` and writes a lock; the build stamp records every digest. The lock is not committed.
- Docs pages in every version may link `/catalogs/opm/` and `/catalogs/opm/<MAJOR>/` and below (the page dialect gains those forms; never a minor or `edge`). `site/tests/lint/` becomes the conformance fixture set docs-kit copies, so the shell lint and `opm-docs lint` agree until phase 3.
- Catalog members leave Reference: when the build has the tab, catalog_opm's `reference/catalog-members/` and `reference/catalog-contract.md` are no longer mounted, and the two links into them that sources still write resolve to the tab, until the sources stop writing them (see Transition).
- The Enhancements plumbing (`ENH_*`, copied in `build-all.sh` and `serve.sh`) is factored into one sourced script before a third section copies it.
- Nothing is **BREAKING** for a docs URL outside the catalog reference; the removed URLs are listed below.

## Transition

There is no window in which the members are published twice (accepted into docs-kit's orchestration, item 12): the build that gains the tab stops mounting catalog_opm's `docs/site/reference/catalog-members/` and `docs/site/reference/catalog-contract.md`, (and the single `catalog-members.md` an older tree holds at the same URL), and resolves the only two link targets sources still write into them (`/docs/reference/catalog-contract/` from cli's `registry-namespaces.md`, twice, and `/docs/reference/catalog-members/` from opm's `reference/glossary.md`, once; catalog_opm's `kubernetes-resources.md`, which also linked it twice, went with the k8s catalog's retirement) as their alias forms, `/catalogs/opm/4/` and `/catalogs/opm/4/#catalog-members` (the landing's generated members block). So nothing publishes twice and no link breaks, whatever order the follow-ups below merge in. The exclusion and the two-entry link map are removed by a follow-up once no source writes the old links and catalog_opm has deleted the pages (`TODO.md`).
